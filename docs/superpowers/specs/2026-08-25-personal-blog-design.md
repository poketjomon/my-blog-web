# 个人博客网站设计文档

日期：2026-08-25
状态：已确认

## 1. 背景与目标

搭建一个个人博客网站，用于记录随笔与学习笔记，并承载个人介绍（学术经历、GitHub 主页）。网站为纯静态架构，本地写 Markdown、通过 git 同步发布，无数据库、无登录后台，部署安全、维护成本低。

### 核心需求

- 文章带日期、分类、标签
- 文章显示字数统计（含阅读时长）
- 支持图片上传（随仓库提交或图床）
- 有「关于」页面：个人介绍、学术经历、GitHub 主页链接
- 发布流程：本地写作 → git push → 自动构建部署

### 明确不做的事（YAGNI）

- 不做后台管理系统（本地 Markdown + git 即管理方式）
- 不做评论系统
- 不做数据库
- 暂不做论文列表页面（当前无论文；未来需要时新增一个页面即可，不影响架构）

## 2. 技术选型

| 组件 | 选型 | 理由 |
|---|---|---|
| 静态生成器 | Hexo | 中文生态成熟，文档齐全，符合"以随笔/学习为主"的内容侧重 |
| 主题 | Butterfly | 自带字数统计、阅读时长、分类、标签、归档，无需额外插件 |
| 托管 | GitHub Pages | 免费，纯静态无攻击面 |
| 自动部署 | GitHub Actions | push 后自动构建并发布，本地无需手动执行部署命令 |

曾对比并排除的方案：

- Hugo + Hugo Blox 学术模板：学术展示能力更强，但用户当前无论文、学术内容占比低，优势无法发挥；且文档以英文为主
- Astro 从零搭建：工作量过大，无必要
- 带后台的 CMS（Halo/WordPress 等）：需要服务器运行服务与数据库，安全风险与维护成本均高于纯静态方案

## 3. 网站结构

### 栏目与导航

- **首页**：文章列表，每项显示标题、发布日期、分类、字数统计
- **分类页**：初始分类为「随笔」「学习」两类，后续可按需新增
- **归档页**：按时间线排列全部文章（主题自带）
- **关于页**：个人介绍、学术经历简述、GitHub 主页链接

### 文章组织

- 文章为 Markdown 文件，位于 `source/_posts/`
- 每篇文章头部 front-matter 包含：标题（title）、日期（date）、分类（categories）、标签（tags，可选）
- 字数统计与阅读时长由 Butterfly 主题根据正文自动计算，无需手动维护

## 4. 图片处理

- 默认方式：图片存放于 `source/images/`，在文章中以相对路径引用，随项目一起 git push（简单可靠）
- 可选增强：安装 PicGo 上传图床，自动获取 Markdown 图片链接；仅在仓库体积明显增大后再考虑，初期不做

## 5. 写作与发布流程

1. 本地新建文章：`hexo new "文章标题"`
2. 编辑 Markdown，本地预览：`hexo server`
3. 发布：`git add` → `git commit` → `git push`
4. GitHub Actions 自动执行：安装依赖 → `hexo generate` → 部署产物到 GitHub Pages

用户的服务器暂不投入使用；未来如需绑定自有域名或改用服务器托管（nginx 提供静态文件），架构无需变更。

## 6. 项目目录（预期）

```
my-blog-web/
├── source/
│   ├── _posts/          # 文章 Markdown
│   ├── images/          # 文章图片
│   └── about/           # 关于页
├── themes/butterfly/    # 主题
├── _config.yml          # 站点配置
├── _config.butterfly.yml # 主题配置
├── package.json
└── .github/workflows/   # GitHub Actions 自动部署
```

## 7. 验收标准

- 本地 `hexo server` 可预览站点，首页、分类、归档、关于页均可访问
- 文章页显示日期、分类与字数统计
- git push 后 GitHub Actions 成功构建并发布到 GitHub Pages
- 至少包含一篇示例文章与「关于」页面内容
